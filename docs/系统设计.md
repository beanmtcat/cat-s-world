# 猫子的世界：前后端系统设计（Halo v2 迁移）

> 版本：0.4（安全基线、国内外搜索兼容与功能清单）
> 内容策略：**PostgreSQL 的 `mmcat_posts.content` / `mmcat_pages.content` 是线上正文唯一事实源；Markdown 文件仅用于导入、导出和离线备份。**

## 1. 目标与边界

把现有 React 首页扩展为一个可长期维护的个人技术站：

- 面向访客：浏览文章、分类、标签、搜索、图库与公开页面。
- 面向作者：在后台创建、编辑、预览、发布 Markdown 文章，管理媒体与页面。
- 面向管理员：管理用户、系统设置、迁移任务、发布记录与回收站。
- 面向迁移：导入 Halo 的文章、分类、标签、附件与基础元数据，并输出标准 Markdown 文件。
- 不把 Halo 运行时数据库作为新系统的依赖；迁移完成后可独立运行。

首期必须实现公众账号注册、邮箱验证、登录后评论、回复与后台审核；禁止游客评论。首期不做会员订阅、多人实时协作编辑和复杂审批流。

## 2. 总体架构

```text
浏览器 / 搜索引擎
        │
        ▼
React 前台（frontend） ────────────────┐
        │ HTTP / JSON                  │ 静态资源 CDN / 对象存储
        ▼                              ▼
REST API（backend） ─────────────── 媒体文件
        │
        ├── PostgreSQL：正文、用户、标签、图库、评论、状态、统计、审计、迁移任务
        ├── content/：Markdown 导入、导出与离线备份
        ├── 搜索索引：PostgreSQL FTS（首期），可替换 Meilisearch
        └── Worker：Halo 导入、图片转存、索引重建、定时发布、状态探测、统计聚合
```

### 固定技术选型（首期）

以下选型是实现约束，不是供实现者再次选择的候选方案；未经设计变更不得替换框架、数据库、任务队列或对象存储方式。

| 层级 | 首期选型 | 原因 |
| --- | --- | --- |
| 前台 | React + Vite + React Router | 延续现有项目，开发成本低。 |
| API | Python 3.12+ + FastAPI + Pydantic | 原生异步支持、自动 OpenAPI 文档，适合 REST 与导入任务。 |
| 数据层 | PostgreSQL + SQLAlchemy 2.0 + Alembic | 类型化 ORM、事务成熟、数据库版本迁移清晰。 |
| 异步任务 | Celery + Redis | 导入、媒体处理、索引、状态探测和统计聚合不阻塞请求。 |
| 正文 | PostgreSQL `text` 保存 Markdown；文件系统用于导入、导出和备份 | 在线读取一致，同时保留 Markdown 的可移植性。 |
| 媒体 | S3 兼容对象存储 | 所有上传统一走 S3，不提供本地持久化模式。 |
| 部署 | Docker Compose + Nginx | 单机可用，后续可拆分。 |

```text

├── frontend/                 # 访客前台 + 管理后台前端

├── content/                  # Markdown 导入、导出与备份目录
│   ├── posts/                # 按语言导出的文章 Markdown
│   ├── pages/                # 按语言导出的独立页面 Markdown
```

图片、附件和导入包统一上传到 S3；Worker 仅可在系统临时目录解压处理，完成后立即清理，不得把用户上传文件持久化到项目目录。`content/` 是 Markdown 导入、导出与备份目录，数据库中的 `mmcat_posts.content` 是在线正文数据源。

## 4. Markdown 内容规范

导入和导出均使用 UTF-8 的 `.md` 文件，按语言分目录，例如 `content/posts/zh-CN/halo-migration.md`：

```md
---
title: 从 Halo 迁移到猫子的世界
slug: halo-migration
locale: zh-CN
translationGroupId: 7bd4d304-94f8-4ba4-9767-7b631b10ac91
summary: 将 Halo 内容转为可维护的 Markdown 文章。
seoTitle: 从 Halo v2 迁移到 Markdown 的完整方案
seoDescription: Halo v2 文章、附件和旧链接迁移到新系统的实施说明。
canonical: https://example.com/posts/halo-migration
robots:
  index: true
  follow: true
structuredDataType: TechArticle
status: published # draft | scheduled | published | archived
publishedAt: 2026-09-25T08:00:00+08:00
updatedAt: 2026-09-25T10:00:00+08:00
categories: [运维]
tags: [Halo, Markdown, 迁移]
cover: https://cdn.example.com/mmcat/covers/halo-migration.webp
visibility: public # public | unlisted | private
source:
  platform: halo
  originalId: post-123
  originalUrl: https://old.example.com/archives/123
---

正文从这里开始。
```

规则：

1. `slug` 在同一 `locale` 内唯一，修改需由 API 负责建立旧链接重定向。
2. 正文和封面使用 S3/CDN 完整 HTTPS URL，例如 `https://cdn.example.com/mmcat/2026/09/image.webp`。
3. Markdown 允许 GFM、代码块、表格、任务列表、Mermaid；原始 HTML 在导入时保留并标记审查。
4. 导入时将 Markdown 正文写入 `mmcat_posts.content`；`contentHash` 用于版本和重复检测，`filePath` 仅记录可选的导入/导出文件位置。
5. 首期支持 `zh-CN` 与 `en-US`；相互翻译的记录共享 `translationGroupId`，缺失译文时回退到站点默认语言。
6. `seoTitle`、`seoDescription`、`canonical`、`robots` 和 `structuredDataType` 为可选导入字段；缺失时使用数据库定义的回退规则。导入不能让草稿、定时、私有或未列出内容进入 sitemap。

### 5.1 关系与约束

```text
mmcat_users 1 ─── N mmcat_posts
mmcat_users 1 ─── N mmcat_pages

mmcat_users 1 ─── N mmcat_recovery_codes
translation_group_id 1 ─── N mmcat_posts       （每种语言最多一条）
translation_group_id 1 ─── N mmcat_pages       （每种语言最多一条）
mmcat_posts N ─── N mmcat_categories       （mmcat_post_categories）
mmcat_posts N ─── N mmcat_tags             （mmcat_post_tags）
mmcat_posts 1 ─── N mmcat_media            （正文附件；封面仅保存完整 URL）
mmcat_users 1 ─── N mmcat_media_uploads
mmcat_import_jobs 1 ─── N mmcat_import_items

mmcat_media 1 ─── N mmcat_gallery_items

mmcat_media 1 ─── N mmcat_ai_tools         （品牌 Logo，可为空）
mmcat_status_nodes 1 ─── N mmcat_status_checks

mmcat_posts / mmcat_pages 1 ─── N mmcat_content_revisions
```

通用约定：所有主键使用 UUID；时间字段使用带时区的 `timestamptz`；所有表包含 `ctime`、`mtime`、`isvalid`；slug、名称和来源标识按语言或业务作用域建立唯一约束。语言代码使用 BCP 47，首期限定为 `zh-CN`、`en-US`。数据库不建立外键，`*_id` 仅作为逻辑关联字段并建立查询索引；Python 服务层在同一事务内校验引用存在性，删除操作执行显式依赖检查、级联失效或拒绝删除，后台任务定期扫描孤儿记录。

### 5.6 搜索与查询索引

首期不额外引入搜索服务，使用 PostgreSQL 生成列或物化搜索向量：

```sql
ALTER TABLE mmcat_posts ADD COLUMN search_vector tsvector;
CREATE INDEX mmcat_posts_search_idx ON mmcat_posts USING GIN (search_vector);
ALTER TABLE mmcat_pages ADD COLUMN search_vector tsvector;
CREATE INDEX mmcat_pages_search_idx ON mmcat_pages USING GIN (search_vector);
COMMENT ON COLUMN mmcat_posts.search_vector IS '文章全文检索向量，由保存事件或重建任务更新。';
COMMENT ON COLUMN mmcat_pages.search_vector IS '独立页面全文检索向量，由保存事件或重建任务更新。';
```

Worker 在文章或独立页面保存成功后按 `locale` 更新 `search_vector`，内容包括标题、摘要、分类、标签和从 `content` 提取的纯文本正文。英文使用 PostgreSQL `english` 配置；中文首期使用 `simple`，需要分词质量时可安装 `pg_jieba`。文章列表使用 `mmcat_posts_listing_idx`，详情页使用 `(locale, slug)` 唯一约束，旧 Halo 地址使用 `mmcat_redirects.from_path` 唯一索引。应用层在更新记录时同步刷新 `mtime`；默认查询只读取 `isvalid = true` 的记录。

### 5.8 站点属性与国际化约定

`mmcat_site_properties` 是单行配置表，不使用 `property_key + property_value`。站点展示属性均为显式字段：

| 属性组 | 明确字段 |
| --- | --- |
| 站点身份 | `site_name_zh/en`、`site_short_name_zh/en`、`site_subtitle_zh/en`、`site_description_zh/en` |
| 品牌资源 | `logo_url`、`favicon_url`、`default_og_image_url`、`avatar_url`、`banner_background_light_url`、`banner_background_dark_url` |
| 语言与时区 | `default_locale`、`supported_locales`、`timezone` |
| SEO | `seo_title_zh/en`、`seo_description_zh/en`、`seo_keywords_zh/en`、`robots_enabled`、`sitemap_enabled` |
| 首页 Banner | `banner_eyebrow_zh/en`、`banner_title_zh/en`、`banner_description_zh/en` |
| 首页按钮 | `primary_button_text_zh/en`、`primary_button_url`、`secondary_button_text_zh/en`、`secondary_button_url` |
| 首页数字 | `problem_scenarios_count`、`reusable_solutions_count`；文章数从 `mmcat_posts` 实时聚合 |
| 首页引言 | `quote_text_zh/en`、`quote_author_zh/en` |
| 联系与社交 | `contact_email`、`github_url`、`rss_url`、`telegram_url` |
| 备案与版权 | `icp_number/url`、`police_record_number/url`、`copyright_start_year`、`copyright_holder_zh/en` |
| 分页 | `posts_page_size`、`comments_page_size` |
| 功能开关 | `comments_enabled`、`analytics_enabled`、`gallery_enabled`、`friend_links_enabled`、`maintenance_mode` |
| 通用字段 | `ctime`、`mtime`、`isvalid` |

通过部分唯一索引保证任意时刻只有一条 `isvalid = true` 的站点配置。公开 `/site` 接口只能返回展示字段和功能开关，不得返回后台存储配置、密钥或内部探测地址。

搜索引擎的站点验证和提交能力不塞进站点属性表，而是由 `mmcat_search_engine_verifications` 一引擎一条记录管理。公开的 meta/文件/DNS 验证值可以受控输出；任何 API 推送令牌只在密钥管理器中保存，数据库仅保存 `credential_secret_ref`。首期内置 `baidu`、`sogou`、`so360`、`shenma`、`bing`、`google` 六个代码，新增引擎必须先扩展 DDL 的白名单和 Adapter，不能让后台任意输入 URL 或请求头。

国际化规则：

1. 文章、独立页面、分类、标签、图库、友情链接和 AI 工具均以“一种语言一条记录”保存，相同内容的译文共享 `translation_group_id`。
2. 中文使用现有无前缀地址，例如 `/posts/{slug}`；英文使用 `/en/posts/{slug}`，避免上线后改变中文文章地址。
3. 页面通过 `translation_group_id` 查找语言切换目标；目标语言不存在时返回默认语言内容，并明确标记实际返回的 `locale`。
4. 每个已发布译文输出自己的 canonical，并为同组译文输出 `hreflang="zh-CN"`、`hreflang="en-US"` 和指向默认语言的 `hreflang="x-default"`。
5. 后台创建译文时复用原记录的 `translation_group_id`，不得通过复制 slug 猜测译文关系。

### 后台模态框规范

后台所有弹出式交互统一使用应用内模态框组件，不得调用浏览器原生 `alert()`、`confirm()` 或 `prompt()`：

1. 新建、编辑、筛选、详情预览、发布、归档、删除、审核、回滚和批量操作均使用统一 `Modal/Dialog`。
2. 普通桌面端模态框设置合理最大宽度；1024px 以下使用全屏或近全屏布局，操作按钮固定在底部。
3. 必须支持焦点锁定、`Esc` 关闭、关闭后焦点归位、遮罩滚动锁定及正确的 `aria-modal`、标题和描述关联。
4. 表单校验错误显示在对应字段附近；提交期间禁用重复操作，关闭前保留未提交状态并二次确认。
5. 删除、回滚、批量失效等危险操作使用专用确认模态框，明确显示目标和影响范围；不可恢复操作要求输入目标名称确认。
6. 长内容预览、Halo 预检报告和图片选择器使用大尺寸模态框；不得在小弹窗中嵌套第二层模态框。

### 路由刷新与地址恢复

前台和管理后台统一使用 React Router 的 `BrowserRouter`，页面状态以当前 URL 为准，不通过刷新后的默认跳转恢复页面：

1. 应用启动时直接解析 `window.location.pathname + search + hash`，禁止在根组件挂载时执行 `navigate('/')`、`location.href = '/'` 或等价重置。
2. 浏览器刷新、复制链接访问和新标签页打开时，必须保留完整 pathname、query string 和 hash；分页、筛选、搜索关键字和当前语言均写入 URL。
3. 未登录访问后台地址时，登录页保存完整 `returnTo`；认证成功后回到原地址，而不是后台首页。`returnTo` 只能接受本站相对路径，防止开放重定向。
4. 未匹配的新站路由显示同地址下的 404 页面，不得重定向首页；Halo 旧地址则优先查询 `mmcat_redirects` 并返回 301/308。
5. 前端部署必须启用 SSR 路由与静态资源回退。旧地址是否重定向由 SSR 在渲染前调用重定向解析接口判定，禁止让静态 `index.html` 抢先返回 `200`。Nginx 示例：

```nginx
location ^~ /api/v1/ {
    proxy_pass http://backend:8000;
}

# Vite 构建产物使用带内容哈希的文件名，可长期缓存。
location ^~ /assets/ {
    root /srv/frontend/dist/client;
    try_files $uri =404;
}

# 其余页面（包括 Halo 旧路径）由 SSR 处理；SSR 先调用 redirects/resolve。
location / {
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_pass http://frontend-ssr:3000;
}
```

SSR 返回的 HTML 用于首屏和 React hydration，不得把未匹配路由伪装成首页。页面组件加载失败时保留当前地址并显示可重试错误状态。

## 7. API 约定

统一前缀：`/api/v1`；读取型公开接口无会话要求，提交评论必须登录并校验 CSRF，后台接口使用同一套 HttpOnly Cookie 会话与更严格的角色授权。

### 7.1 通用协议

1. 请求和响应均使用 `application/json; charset=utf-8`；S3 直传本身除外。数据库和 Python 内部使用 `snake_case`，HTTP JSON 字段统一使用 `camelCase`，由 Pydantic alias 明确转换，禁止同一接口混用两种命名。
2. 时间一律返回带时区的 RFC 3339 字符串，服务端和数据库内部保存 UTC；日期使用 `YYYY-MM-DD`。UUID 使用小写标准字符串，布尔值不得用 `0/1` 代替。
3. 单项成功响应为 `{"data": {...}, "meta": {"requestId": "uuid"}}`；创建返回 `201`，删除或失效成功返回 `204`，异步任务返回 `202` 和任务 ID。
4. 列表响应为 `{"data": [...], "meta": {"requestId": "uuid", "page": 1, "pageSize": 20, "total": 0, "totalPages": 0}}`。`page >= 1`，`pageSize` 默认读取站点配置并限制在 `1..100`；排序参数只允许接口声明的白名单字段。
5. 错误响应统一为 `{"error": {"code": "POST_SLUG_CONFLICT", "message": "...", "fields": {}, "requestId": "uuid"}}`。公开 `message` 可本地化，前端逻辑只判断稳定的 `code`，不得解析文案。
6. 参数校验失败返回 `422`，未认证 `401`，无权限 `403`，不存在或已失效 `404`，版本冲突或唯一键冲突 `409`，频率限制 `429`，未知错误 `500`；`500` 不返回堆栈、SQL 或密钥信息。
7. 所有请求接受或生成 `X-Request-ID`；仅接受合法 UUID，否则重新生成。响应回传同一值，后台写操作将其写入审计日志。
8. 创建、发布、回滚、上传完成、评论提交和导入执行支持 `Idempotency-Key`。服务端以“用户/匿名主体 + 路由 + Key”去重 24 小时；相同 Key 和不同请求体返回 `409 IDEMPOTENCY_KEY_REUSED`。
9. 文章和独立页面的更新、发布、归档、修订恢复必须携带上次 GET 返回的强 ETag 到 `If-Match`；不匹配返回 `409 CONTENT_VERSION_CONFLICT`，并返回最新 ETag，禁止静默覆盖。
10. CORS 仅允许配置的前台域名并允许凭据；生产环境校验 `Host`/`X-Forwarded-*`，只信任明确配置的代理网段。

写入文章的事务：校验 `locale` 与 `translation_group_id` → 规范化 Markdown → 同一数据库事务写入 `content`、元数据和搜索/备份 Outbox 事件 → 提交 → Outbox Worker 触发索引及可选 Markdown 备份任务。数据库提交失败时业务数据和事件一并回滚，并返回可恢复错误。

首期评论流程：校验有效会话、`status=active` 和 `email_verified_at` 非空 → 校验评论目标存在且允许评论 → 若为回复，校验父评论与目标文章/页面一致 → 从用户表复制 `display_name` 到 `author_name`，忽略客户端提供的作者信息 → Markdown/HTML 清洗、长度限制、蜜罐和 Redis 频率限制 → 对 IP 与 User-Agent 加盐哈希 → 写入 `pending` → 后台通过统一审核模态框批准、拒绝或标记垃圾评论。未登录、待验证、禁用或失效账号一律不得提交评论。评论作者可修改自己的有效评论，修改后清除审核信息并重新进入 `pending`；作者删除评论时设为失效，若存在有效回复则公开端显示“该评论已删除”占位而不泄露原文。公开接口只返回 `approved` 评论或必要的删除占位；用户邮箱、IP 哈希、User-Agent 哈希和审核信息永不返回。

## 8. Halo 迁移设计

### 8.1 输入与适配器

首期目标为 Halo v2，不直接绑定 Halo v2 的单一内部表结构。导入器分为两层：

```text
Halo v2 备份包 / 导出文件 / API 拉取
              │
              ▼
        HaloV2Adapter（封装 Halo v2 备份、导出与 API 格式）
              │ 标准化 ImportDocument
              ▼
      ContentWriter + MediaMigrator + IndexWriter
```

首期提供 Halo v2：

1. **文件导入**：上传 Halo v2 导出的 ZIP、JSON/YAML 与附件目录。
2. **Markdown 导入**：直接接收已有 `.md` 文件和前置元数据。
3. **可选在线迁移**：填写 Halo v2 API 地址和只读 Token，由适配器拉取；不保存 Token。

导入界面默认使用 Halo v2；格式无法识别时只允许“预检”，不允许执行导入。

### 8.2 Halo v2 详情页 URL 兼容

Halo v2 的文章详情页默认使用 `/archives/{slug}`，但站点也可能配置为使用文章 `metadata.name`、查询参数、日期路径或分类路径。迁移不能只保存新 slug，必须保存每篇文章的原始永久链接和源文章标识。

支持的旧路径模板：

```text
/archives/{slug}
/archives/{name}
/?p={slug}
/?p={name}
/{year}/{slug}
/{year}/{month}/{slug}
/{year}/{month}/{day}/{slug}
/categories/{categorySlug}/{slug}
```

处理规则：

1. 导入时读取 Halo v2 的 `status.permalink`；无法读取时按导入设置中的旧主题路由模板生成候选地址。
2. 将每个候选地址写入 `mmcat_redirects`，Halo 导入内容默认标记为 `zh-CN`，目标为新站 `/posts/{slug}`，响应 `301`。
3. 查询参数形式必须保留完整 query string，至少支持 `/?p=...`，不能只按 pathname 匹配。
4. 日期路径按文章发布时间生成，月份和日期固定两位；分类路径同时记录分类 slug。
5. 新文章页面输出当前语言的唯一 canonical URL、Open Graph URL、sitemap URL 以及同组译文的 `hreflang`，避免旧地址与不同语言页面被搜索引擎误判为重复内容。
6. 内链迁移时先用 `sourceId`、原始 URL、旧 slug 三层映射替换；找不到映射的链接保留原值并出现在迁移报告中。

API 约定：

```text
GET /archives/:slug                 -> 301 /posts/:slug
GET /archives/:name                 -> 301 /posts/:slug
GET /:year/:slug                    -> 301 /posts/:slug
GET /:year/:month/:slug             -> 301 /posts/:slug
GET /:year/:month/:day/:slug        -> 301 /posts/:slug
GET /categories/:category/:slug     -> 301 /posts/:slug
GET /?p=:name                       -> 301 /posts/:slug
```

路由解析必须在公开文章路由之前执行，并对无法映射的旧地址返回可索引的 404 页面，而不是静默跳到首页。

### 8.4 转换规则

| Halo 内容 | 目标正文 / 数据 |
| --- | --- |
| 标题、摘要、发布时间、状态 | 写入 `mmcat_posts` 对应字段。 |
| HTML 正文 | Turndown 转 GFM 后写入 `content`；代码块、表格、图片单独处理。 |
| 已是 Markdown 的正文 | 将媒体上传到 S3并改写为完整 URL 后写入 `content`。 |
| 分类、标签 | 规范化为当前语言的 slug，写入对应关联表。 |
| 封面、正文图片、附件 | 下载到受限临时目录，经相同的类型、恶意内容、解码和元数据清理流程后上传到 S3，校验 checksum，将正式完整 URL 写入 `source_url` 或对应 `cover_url`。 |
| 原始文章 ID 与 URL | `source` 字段与 `mmcat_redirects`。 |
| 未支持短代码或插件块 | 保留为注释/原始 HTML，并写入 `warnings`。 |

### 8.5 导入流程

1. 上传或连接导入源，创建 `mmcat_import_jobs` 记录。
2. 适配器解析数据，统计文章、独立页面、草稿、分类、标签、媒体数量。
3. **预检**：校验必填字段、重复 slug、无法下载媒体、不可转换 HTML；展示可编辑的映射与警告。
4. 用户确认后，Celery Worker 逐条转换正文，默认标记为 `zh-CN`，并准备数据库写入数据。
5. 媒体先进入 S3 quarantine，验证 checksum、尺寸、真实 MIME、恶意内容和对象键安全；扫描通过、移动到正式对象键并经 `HeadObject` 校验后，才写入完整 `source_url`。
6. 同一数据库事务写入正文、索引字段、分类、标签、重定向与后续任务 Outbox；提交后由 Outbox Worker 异步生成可选的 Markdown 备份。
7. 重建全文索引，生成报告：成功数、跳过数、失败数、警告与产物路径。
8. 在可配置保留期内，管理员可按 `jobId` 回滚本次新建内容和媒体引用。

### 8.6 链接与 SEO

索引规则由服务端强制执行，后台填写的 `robots_index` 不能绕过状态与可见性：

| 内容状态 | HTTP 与 robots | 列表 / sitemap / RSS |
| --- | --- | --- |
| `draft`、`scheduled` | 公开地址返回 404；后台预览返回 `noindex, nofollow` 与 `Cache-Control: no-store` | 全部排除 |
| `published + public + robots_index=true` | `200 index`，follow 取 `robots_follow` | 全部包含 |
| `published + public + robots_index=false` | `200 noindex` | sitemap 排除，RSS 可按站点策略排除 |
| `published + unlisted` | `200 noindex, follow`，知道地址可访问 | 列表、搜索、sitemap、RSS 全部排除 |
| `private` | 未授权统一返回 404，禁止泄露标题和元数据 | 全部排除 |
| `archived` 或软删除 | 有替代内容则 301/308；否则 410，短期保留 `noindex` 错误页 | 全部排除 |

具体规则：

1. SSR 首次 HTML 必须包含正文、唯一 `<title>`、meta description、自引用 canonical、Open Graph/Twitter Card、语言、BreadcrumbList 和 Article/BlogPosting/TechArticle JSON-LD；不得等待客户端 JavaScript 注入关键 SEO 信息。
2. `seo_title`/`seo_description` 为空时回退 `title`/`summary`；分享图依次回退 `og_image_url → cover_url → default_og_image_url`。后台显示搜索摘要和分享卡片预览，并提示缺失标题、描述、alt、封面或异常长度，但不机械截断正文数据。
3. canonical 默认由受信任的 `APP_BASE_URL + locale 路由 + slug` 生成；自定义值只允许完整 HTTPS URL。canonical、站内链接、sitemap 和 hreflang 必须一致，不得为同一页面输出多个 canonical。
4. 每个已发布译文输出指向同语言 canonical 的 `hreflang`，并输出默认语言 `x-default`；不存在的译文不生成虚假链接。
5. sitemap 只包含可索引 canonical URL，`lastmod` 仅在正文、标题、SEO、封面或结构化数据实际变化时更新；拆分文章、页面、图库 sitemap，并由 sitemap index 汇总。
6. RSS 只输出公开已发布文章，正文可配置全文或摘要；条目 GUID 使用稳定 canonical，改 slug 后通过旧地址 301 保持连续性。
7. 分类、标签和分页提供可抓取 `<a href>`；筛选组合、站内搜索结果、登录、账户、后台和预览页面统一 `noindex`。无限滚动必须同时提供独立分页 URL。
8. 图片输出真实 `src`、宽高、描述性 alt、响应式 `srcset` 和懒加载；首屏主图不得依赖滚动或点击才出现，并避免造成布局偏移。
9. 保留 `originalUrl`，自动生成 `/archives/:id`、旧 slug 和旧 permalink 的服务端 301/308；禁止 JavaScript 重定向。内链先按 URL 映射改写，未命中的链接原样保留并写入报告。
10. robots.txt 只管理抓取，不用于 canonical 或移除已索引页面；需要移除时返回 410 或可抓取的 `noindex`。404/410 必须返回真实状态码，不能返回首页 `200`。
11. 发布或更新事务写入缓存、sitemap、RSS 与搜索索引 Outbox；任务完成前旧版本可短暂保留，但不得出现 canonical 指向新地址而正文仍为旧版本的混合缓存。
12. 上线验收使用禁用 JavaScript的原始 HTML、Rich Results Test、Search Console URL Inspection、sitemap 校验和旧 URL 抽样，不以浏览器最终 DOM 看起来正确作为唯一标准。

#### 国内搜索引擎兼容

1. 首期必须在后台分别维护并验证百度、搜狗、360 与神马站长平台；验证方式由 `mmcat_search_engine_verifications` 明确记录。验证 meta 标签、HTML 验证文件或 DNS 记录只能由 SSR/Nginx 按已启用配置输出，禁止通过前端运行时注入或把后台路径暴露给验证爬虫。
2. 全站响应式设计使用同一 canonical URL，不做按 User-Agent 跳转的独立 m 站；所有搜索引擎和普通访客收到同一份语义等价的 SSR HTML、状态码、正文、链接和 meta，禁止 cloaking（向爬虫展示不同正文）。移动端首屏正文、标题、图片和主操作不得依赖点击、横向滚动或未展开菜单。
3. 标准 `/sitemap.xml` 与 sitemap index 继续服务于通用爬虫；同时生成百度平台可直接提交的、**不含 sitemap index 嵌套**的 URL 列表文件，例如 `/sitemaps/baidu-posts-001.xml`。每个文件只含当前验证站点的可索引 canonical URL；发布/撤回/改 slug 后由 Outbox 增量更新。若在百度平台启用移动 Sitemap，则同一批 URL 输出 `mobile:mobile type="pc,mobile"`，不另造移动 URL。
4. 百度配置通过验证后可启用“普通收录” API Adapter；Adapter 只从可信发布事件读取公开 canonical URL，逐条限流、重试和记录脱敏结果，永不提交草稿、预览、搜索页、未列出页、私密页、重定向地址或用户输入 URL。API 配额、平台权限或接口变更时自动降级为 sitemap 提交，不能阻塞文章发布。搜狗、360、神马同样保留验证、sitemap 与监控流程；除非其当期官方平台明确开放并在验收环境通过，否则不假设存在 URL 推送 API。
5. 国内标题与描述使用自然中文，页面必须有可见发布日期、更新时间、作者、分类、面包屑、正文和图片 alt；禁止关键词堆砌、隐藏文字、采集拼接、伪原创或自动生成无人工审校的批量内容。`seo_keywords_zh` 仅作为站内运营字段，不承诺所有搜索引擎使用该 meta。
6. 后台提供“搜索引擎验证与提交”模态框：仅站点管理员可操作，展示验证状态、最近提交时间、成功/失败数量、脱敏错误和平台跳转链接；不得展示 API token。每次启停、验证状态手工确认或提交策略调整必须写 `mmcat_audit_logs`。
7. 上线与迁移验收除 Google/Bing 外，必须用百度、搜狗、360、神马的真实移动 UA 抓取公开文章、分类、标签、图库和旧 Halo URL，断言返回与普通访客相同的 SSR HTML、canonical、中文编码、`200/301/404/410`；随后在各平台提交 sitemap、抽样查看收录/抓取异常并建立月度巡检任务。

## 9. 权限、安全与备份

### 登录与密码安全基线

1. **传输安全**：登录、刷新、改密和重置接口只允许 HTTPS；生产环境启用 HSTS。密码不得进入 URL、日志、异常信息、审计 `payload` 或监控标签。
2. **密码存储**：使用 Argon2id 和每个密码独立随机盐，首期参数至少为 `memory_cost=65536 KiB`、`time_cost=3`、`parallelism=2`、输出 32 字节；参数写入哈希字符串，登录成功时发现参数过旧则自动重新哈希。服务端可选 pepper 必须来自密钥管理服务或环境变量，不能入库。
3. **密码策略**：长度 15–128 个 Unicode code point，允许密码管理器、粘贴、空格和 Unicode；哈希前使用 NFC 规范化但不得静默 trim 或改变大小写。拒绝常见弱密码、与邮箱相同的密码及已配置的泄露密码词库，不强制无意义的大小写/符号组合，也不定期强制改密；确认泄露或账号接管时强制改密。
4. **防爆破计数**：Redis 使用原子操作同时维护“标准化账号 + IP”“账号”“IP”三个维度的滑动窗口；数据库中的 `failed_login_count`、`locked_until` 用于持久化账号锁定状态。
5. **重试退避**：第 1–2 次失败允许正常重试；第 3 次开始按 `2^(n-3)` 秒递增等待，单次最多 60 秒；同一账号 15 分钟内失败 5 次锁定 15 分钟，持续攻击可递增到 1 小时。成功登录后清空连续失败计数。
6. **验证码与限流**：同一账号或 IP 连续失败 3 次后要求验证码；单 IP 默认最多 10 次/10 分钟、单账号最多 5 次/15 分钟。验证码通过不能绕过密码失败计数和速率限制。
7. **防账号枚举**：账号不存在、密码错误、账号锁定的公开响应统一为相同状态码和通用文案，并执行相近耗时的虚拟 Argon2id 校验；具体原因只写入 `mmcat_login_logs`。
8. **客户端重试**：前端不得自动重放错误密码；遇到 `429` 时读取 `Retry-After`，禁用提交按钮并显示倒计时。网络错误最多自动重试一次，且不得重复创建会话。
9. **会话安全**：成功登录后生成至少 256 bit 随机会话 Token，数据库只保存 SHA-256 摘要；登录和刷新时轮换 Token，防止会话固定。首期前后端同站部署，Cookie 使用 `__Host-` 前缀、`HttpOnly + Secure + SameSite=Strict + Path=/` 且不设置 `Domain`，空闲 30 分钟、绝对有效期 30 天；改密、账号禁用后撤销该用户全部会话。
10. **CSRF 与来源校验**：所有改变状态的 Cookie 鉴权请求校验 CSRF Token 和 `Origin`；登录接口同样启用频率限制，不因未登录而豁免。
11. **密码重置**：令牌使用至少 256 bit CSPRNG 生成，数据库只保存 SHA-256 摘要，15 分钟过期且只能使用一次；新申请会使旧令牌失效。无论邮箱是否存在，忘记密码接口均返回相同响应。
12. **日志与告警**：每次成功、失败、锁定、刷新、退出、改密和重置都写入 `mmcat_login_logs`；短时间内跨 IP 攻击同一账号或单 IP 攻击多个账号时触发安全告警。
13. **注册与邮箱验证**：注册接口按 IP 和规范化邮箱限流，密码规则与登录一致；新账号状态为 `pending_verification`。验证令牌至少 256 bit、数据库只保存 SHA-256 摘要、24 小时过期且一次性使用，重新发送会使旧令牌失效。验证成功后原子更新 `email_verified_at` 和 `status=active`。
14. **评论认证**：`POST /comments` 必须有有效会话、CSRF Token、`active` 状态和已验证邮箱；缺少会话返回 `401 COMMENT_LOGIN_REQUIRED`，待验证返回 `403 EMAIL_NOT_VERIFIED`，禁用账号返回通用 `403 ACCOUNT_NOT_AVAILABLE`。不得接受客户端提交的用户 ID、作者名或邮箱。
15. **初始管理员**：部署时只允许通过容器内 CLI `python -m app.cli create-superuser` 创建首个 `admin`，交互读取密码或从一次性文件读取，禁止默认账号、默认密码和将密码放入命令行参数；创建完成后立即写入审计日志并要求首次登录改密。

### 特权账号、MFA 与会话加固

1. `admin`、`editor`、`author` 进入 `/studio` 必须完成密码 + WebAuthn 两步认证；`member` 可选 Passkey。WebAuthn 按站点正式域名固定 RP ID 和允许 Origin，必须校验 challenge、RP ID hash、Origin、签名、用户在场和用户验证标志。
2. 密码验证成功后若需要 MFA，只在 Redis 创建 5 分钟、单次使用、绑定账号/IP 摘要/User-Agent 摘要的登录事务，不得提前签发正式会话。MFA 连续失败也进入账号与 IP 限流。
3. 后台账号首次登录只允许进入 MFA 绑定流程；绑定成功前不能访问其他后台 API。`admin` 至少绑定一个 WebAuthn 凭据并生成 10 个一次性恢复码，界面明确建议绑定两个不同设备。
4. WebAuthn challenge 使用至少 256 bit CSPRNG、最长 5 分钟、验证成功或失败达到上限后立即删除；challenge、私钥和恢复码明文不得写入 PostgreSQL、日志或前端持久化存储。
5. 恢复码每个至少 128 bit 随机熵，只展示一次，数据库保存 keyed HMAC；使用、重新生成恢复码或移除凭据都会撤销旧恢复码、轮换会话并发送安全通知。
6. 改密、改邮箱（若后续开放）、变更角色、关闭 MFA、删除最后一个凭据、查看完整安全日志、导出数据和执行迁移回滚要求 10 分钟内完成过密码或 WebAuthn 的 step-up 验证。
7. 权限提升、密码修改、MFA 恢复或高风险登录后轮换会话 Token。会话 Cookie 固定使用 `__Host-` 前缀、`Secure`、`HttpOnly`、`Path=/`、不设置 `Domain`，首期同站部署使用 `SameSite=Strict`；Cookie 不得复制到 localStorage/sessionStorage。
8. 登录、登出和撤销全部会话的响应添加 `Cache-Control: no-store`；登出同时返回 `Clear-Site-Data: "cache", "cookies", "storage"`，但不得清除用户主动下载的恢复码文件。

### 其他安全与备份

- `admin`：设置、用户、迁移、回滚、删除；`editor`：内容与媒体；`author`：仅自己的内容。
- 所有管理写操作记录审计日志；上传校验扩展名、MIME、体积和内容签名。
- 授权默认拒绝，服务层同时校验角色、资源所有权和资源状态；列表查询也必须施加所有权过滤，防止通过枚举 UUID、批量接口、导出或搜索结果形成 IDOR。请求 Schema 禁止额外字段，防止 mass assignment 修改 `role`、`status`、`author_id`、`isvalid` 等服务端字段。
- API 与 SSR 默认发送 CSP（使用 nonce，禁止 `unsafe-eval`）、`frame-ancestors 'none'`、`X-Content-Type-Options: nosniff`、严格 `Referrer-Policy`、最小 `Permissions-Policy` 和 HSTS；第三方脚本默认禁止，引入时必须固定来源、使用 SRI 并更新 CSP。
- 数据库使用迁移账号、应用读写账号、只读报表账号和审计写入账号四类最小权限角色；运行时应用账号没有建表、扩展、角色管理权限。审计表对普通应用角色禁止 UPDATE/DELETE，专用函数只允许 INSERT；审计归档与清理使用单独受控作业并再次记录审计。
- Redis 不保存永久事实源，认证挑战、速率限制和幂等记录设置 TTL。Redis 不可用时登录、注册、重置密码、评论和后台写操作 fail closed 返回 `503 SECURITY_DEPENDENCY_UNAVAILABLE`，公开只读页面可降级继续服务。
- 上传先进入私有 quarantine 对象前缀；服务端校验文件头、解码后的真实类型、尺寸、像素总量、压缩比和 checksum，并执行恶意文件扫描。通过后重新编码允许的图片格式、剥离 EXIF/GPS，拒绝 SVG/HTML/脚本型内容，再移动到正式对象键并写入 `source_url`。失败对象在短保留期后清理。
- S3 Bucket 禁止公开列目录和 ACL，服务端凭据仅允许规定前缀与必要动作；启用服务端加密、版本控制、访问日志和生命周期。预签名策略限制对象键、长度、类型、checksum 和到期时间，完成接口只接受当前用户创建的 upload ID。
- 后台审计日志保存真实客户端 IP 时，仅信任受控反向代理写入的转发头；列表默认脱敏显示，导出仅限 `admin`，并按安全策略设置保留期。
- 每次登录成功、登录失败、退出、会话刷新和账号锁定都必须写入 `mmcat_login_logs`；即使账号不存在也记录脱敏账号、IP 和失败原因，但接口响应不得暴露账号是否存在。
- 登录日志默认保留 180 天，后台仅 `admin` 可查看；页面默认脱敏账号和 IP，完整导出本身也必须写入审计日志。
- 评论必须由已登录且邮箱已验证的有效用户提交，并默认进入 `pending`；接口继续启用按用户和 IP 的频率限制、蜜罐字段和垃圾内容检测，邮箱永不通过公开 API 返回。
- 访问统计不保存明文 IP；访客哈希使用可轮换盐值，原始事件按保留期清理，只长期保留 `mmcat_visit_daily` 聚合数据。
- 状态探测由 Celery Beat 调度；公开接口只返回节点名称、状态、延迟和检查时间，不暴露内部 `endpoint` 或错误详情。
- 导入文件解压必须防 Zip Slip、路径穿越和压缩炸弹。
- 业务写入与 `mmcat_outbox_events` 在同一数据库事务提交；Outbox Worker 使用 `FOR UPDATE SKIP LOCKED` 抢占、指数退避和幂等消费者。不得再使用“提交后直接发送 Celery，失败后尽量补偿”作为唯一交付机制。
- 每日备份 PostgreSQL 与 `content/` 导出；备份使用独立密钥加密、跨账号或不可变存储保存，S3 开启版本控制、生命周期和定期 Inventory。每季度执行恢复演练并记录 RPO/RTO；备份成功不等于恢复成功。
- CI 执行密钥扫描、依赖锁定与漏洞扫描、SAST、生成 SBOM、容器以非 root 用户运行并固定基础镜像 digest；生产镜像不得包含测试数据、`.env`、源码密钥、包管理缓存或调试器。
- 日志结构化输出并限制字段；对认证异常、权限拒绝激增、审计写入失败、Outbox 积压、恶意上传、SSRF 拦截、备份失败和状态探测异常设置告警。安全日志时间由可信 NTP 同步，访问受最小权限控制。

安全验收以 [OWASP ASVS 5.0.0](https://github.com/OWASP/ASVS/tree/v5.0.0_release) Level 2 为最低基线，并结合 [OWASP Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)、[File Upload](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html)、[SSRF Prevention](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)、[NIST SP 800-63B-4](https://pages.nist.gov/800-63-4/sp800-63b.html) 和 [WebAuthn Level 3](https://www.w3.org/TR/webauthn-3/) 建立可追踪测试项。涉及后台权限、认证器恢复、迁移、备份和审计的控制按更高风险处理，不能仅以普通博客的低风险假设豁免。

## 10. 实施里程碑

1. **基础骨架**：初始化 Python 3.12、FastAPI、SQLAlchemy、Alembic、PostgreSQL、Celery 与 Docker Compose。
2. **首期内容与评论闭环**：数据库 Markdown 正文、文章封面、独立页面、修订历史、公开列表/详情、后台登录、中英文编辑、评论发布/回复/审核/反垃圾。
3. **首页与互动**：分类、标签、导航、AI 工具、站点状态、图库和友情链接。
4. **媒体与发布**：上传、引用、草稿、定时发布、全文搜索、访问统计和站点设置。
5. **Halo 迁移**：导入适配器、预检、转换、媒体迁移、报告、回滚与重定向。
6. **上线质量**：权限测试、迁移样本测试、备份恢复演练、性能与 SEO 验收。

## 11. 验收标准

- 后台发布一篇文章后，数据库正文、封面、搜索索引和前台页面一致。
- 首期必须完成公众账号注册、邮箱验证、登录后评论、树形回复、待审核队列、批准/拒绝/垃圾标记、限流、隐私字段保护和后台模态框审核操作；未登录访客只能阅读评论，任何入口都不得提交评论。
- 后台登录可查看并撤销其他会话；发布前自动保存修订，管理员可从修订历史恢复文章或独立页面。
- 每条后台敏感操作审计记录包含请求 ID、操作者、IPv4/IPv6、User-Agent、请求方法、路径、执行结果和变更摘要。
- 登录成功、失败、退出、刷新和锁定事件均可按账号、IP、时间和结果检索，并能关联到对应请求 ID 与会话。
- 连续提交错误密码时依次触发延迟退避、验证码、`429 + Retry-After` 和临时锁定；不存在的账号与真实账号失败时使用一致的公开响应，响应耗时保持在合理的相近范围。
- 数据库、应用日志、审计日志和错误响应中不得出现明文密码、会话 Token 或密码重置 Token；修改或重置密码后，旧会话和未使用的旧重置令牌立即失效。
- 所有 `/studio` 角色必须通过 WebAuthn MFA；密码验证完成但 MFA 未完成时不得签发正式会话，恢复码不可重复使用，敏感操作必须通过 step-up。
- 上传文件在 quarantine 完成真实类型、恶意内容、图片解码和元数据清理前不得获得正式 `source_url`；SVG、HTML 和脚本型文件默认拒绝。
- 普通应用数据库账号不能 UPDATE/DELETE 审计日志；业务写入与 Outbox 同事务提交，在模拟 Broker 故障后仍能恢复投递且消费者不重复产生业务结果。
- 后台所有弹出式交互均使用统一应用内模态框，并通过键盘导航、焦点锁定和移动端全屏模式验收。
- 在文章、图库、独立页面、搜索结果或任意后台子页面刷新浏览器后，pathname、查询参数、锚点和当前页面保持不变；未登录后台页面完成登录后返回原地址。
- 首页分类、最新文章、AI 工具、站点状态、热门标签、引言和备案信息均来自明确的数据表或站点属性，不在前端写死业务数据。
- 从 Halo 迁移 100 篇含图片文章时，可显示预检结果、失败原因和可回滚记录。
- 已迁移文章正文中 95% 以上的常见 HTML/GFM 结构可无人工修复渲染；其余有明确告警。
- 原 Halo 文章 URL 能通过 301 进入对应新文章或明确的迁移报告页。
- 1024px 以下使用紧凑前台布局，桌面内容区最大 1200px。

## 12. AI Coding 实施契约

本节用于消除自动生成代码时最容易出现的自由发挥。AI 或人工实现均必须把本文当作规范，而不是需求草稿。

### 12.1 规范优先级与禁止事项

1. 冲突时依次以“最新数据库 DDL → API 通用协议与端点 → 状态机 → 页面清单 → 示例”为准；发现仍无法判定的冲突时停止该模块实现并记录设计问题，不得自行创建另一套模型。
2. 数据库表名、列名、枚举值、API 路径和 JSON 字段名属于稳定契约。不得擅自改名、添加外键、把 S3 改成本地上传、把数据库正文改成文件正文或把 `/studio` 改成常见管理路径。
3. 新增表、字段、枚举、路由或环境变量时，必须同时更新 Alembic、SQLAlchemy Model、Pydantic Schema、OpenAPI、测试和本文；禁止只让前端适配临时字段。
4. DDL 中没有数据库外键是明确决策，不代表没有完整性校验。每个写用例必须在同一事务中校验逻辑引用；定时孤儿扫描只能兜底，不能代替写入校验。
5. `isvalid=false` 表示逻辑删除或系统失效，所有普通查询默认过滤；`status` 表示业务生命周期，两者不得混用。关联表恢复时更新原记录，不插入与复合主键重复的新记录。
6. slug、旧路径和已公开 URL 默认永久保留，不允许删除后被其他内容复用；需要更名时先创建重定向，再提交新 slug。

### 12.2 固定状态机

| 对象 | 允许状态变化 | 禁止或特殊规则 |
| --- | --- | --- |
| 文章/页面 | `draft → scheduled → published → archived → draft`；`draft → published`；`scheduled → draft` | `scheduled` 必须有未来的 `scheduled_at`；`published` 必须有 `published_at`；归档不删除正文与重定向。 |
| 图库 | `draft → published → archived → draft` | 公开图库必须至少有一个有效图片项。 |
| 评论 | `pending → approved/rejected/spam`；`spam/rejected → pending`；作者修改时 `approved → pending` | 公开端只读 `approved` 或必要删除占位；父评论失效时回复仍保留但不单独成为顶级评论。 |
| 用户 | `pending_verification → active → disabled`；管理员可将 `disabled → active` | 公开注册只能创建 `member + pending_verification`；邮箱验证仅激活 pending 账号，不能恢复管理员禁用账号。 |
| 导入任务 | `uploaded → validating → ready → running → completed/failed → rolled_back` | 只有 `completed` 可回滚；同一任务执行和回滚均要求幂等锁。 |
| 导入明细 | `pending → converted → imported/skipped/failed` | 已导入项重试时按 `source_platform + source_id` 更新或跳过，不重复创建。 |
| 媒体上传 | `initiated → uploaded → scanning → ready`；任一步可进入 `failed/expired` | 只有 `ready` 才创建 `mmcat_media` 和正式 `source_url`；失败或过期对象不得被内容引用。 |
| 会话 | `active → rotated/revoked/expired`（由时间字段表达） | 轮换后旧 Token 立即无效；禁用账号和改密撤销全部会话。 |

状态变化只能由服务层用例执行，路由层不得直接修改 ORM 状态。定时发布 Worker 使用数据库行锁或原子条件更新抢占任务，确保多个 Worker 不会重复发布。

```text
backend/app/
├── api/v1/              # FastAPI 路由，仅解析协议、鉴权并调用 service
├── core/                # 配置、日志、安全、错误码、请求 ID
├── db/                  # session、SQLAlchemy models、Alembic 接入

├── repositories/        # 查询与持久化，不承载权限和业务状态机
├── services/            # 事务、权限、状态机、幂等和逻辑引用校验
├── tasks/               # Celery 任务；只调用可复用 service
├── integrations/        # S3、Halo v2、邮件、状态探测
└── tests/               # unit、integration、contract、security

frontend/src/
├── app/                 # Router、Provider、错误边界和主题
├── api/                 # OpenAPI 生成客户端及统一错误处理
├── features/            # posts、comments、media、imports、settings 等业务模块
├── pages/               # 路由页面，只组合 feature
```

路由层、React 页面和 Celery Task 不得复制业务规则。事务边界放在 `services`；Repository 不执行 `commit`，由 Service 统一提交或回滚。所有 Python 模块开启类型检查，前端开启 TypeScript strict；禁止使用无说明的 `Any`、裸字典响应和散落的字符串错误码。

### 12.4 SEO 渲染决策

仅靠浏览器执行 JavaScript 不能作为旧 Halo 搜索权重迁移的唯一保障。公开首页、文章、独立页面、分类、标签和图库路由必须在首次 HTTP 响应中包含可读正文或摘要、`title`、description、canonical、Open Graph、JSON-LD 和 `hreflang`，不得等 React 挂载后才补齐。

首期采用 **Vite SSR + React hydration**：`frontend` 同时提供 client 与 server entry，SSR 层通过 Python API 读取数据；Python/FastAPI 仍是唯一业务后端。Nginx 把 `/api/v1` 交给 FastAPI、静态资源交给 CDN、其余页面交给 SSR。SSR 在渲染前把原始 pathname 与规范化 query 传给 `/api/v1/redirects/resolve`；命中时直接返回 API 指定的 `301/308 + Location`，未命中才继续路由渲染。解析接口只返回数据库中已验证的站内相对目标，不接受调用方提供目标地址，避免开放重定向。SSR API 超时返回带正确状态码的错误页，不能回退成首页 `200`。发布、改 slug 或撤回后必须失效对应 SSR/CDN 缓存。不得依据百度、搜狗、360、神马或其他爬虫 User-Agent 改变正文、canonical、状态码或链接，只允许对已登记验证路径返回同样安全的验证内容。

### 12.6 异步任务与一致性

- 必须实现：定时发布、搜索索引更新、Halo 导入、S3 媒体迁移、状态探测、访问统计聚合、邮件通知、Markdown 导出、过期会话/令牌/幂等键清理、孤儿逻辑引用扫描。
- 每个任务有稳定名称、输入 Schema、最大重试次数、指数退避、超时和幂等键；任务参数只传资源 ID，不传密码、Token 或大段正文。
- 业务变更与 `mmcat_outbox_events` 在同一事务提交；独立 Outbox Worker 抢占事件并投递 Celery，消费者按 `idempotency_key` 去重。不得在数据库事务未提交时发送邮件、删除 S3 对象或刷新 CDN；周期性补偿扫描仅用于修复异常 Outbox，不作为主投递方案。
- 删除媒体前查询文章正文、封面、页面、图库和 AI 工具的全部引用；存在引用时返回 `409 MEDIA_IN_USE`。数据库失效成功但 S3 删除失败时进入重试，不回滚为可见状态。

### 12.7 输入、渲染与网络安全

- Markdown 在服务端使用允许列表清洗后渲染；禁用脚本、事件属性、危险协议、任意 iframe 和未经允许的内联样式。代码高亮与 Mermaid 在隔离策略下运行，并配置 CSP。
- `url`、`logo_url`、导航地址和重定向目标只允许站内相对路径或 `http/https`；拒绝 `javascript:`、`data:`、凭据 URL 与控制字符。外链新窗口自动加入 `noopener noreferrer`。
- 状态探测、Halo 在线迁移和远程媒体下载都属于 SSRF 风险：解析 DNS 后拒绝环回、链路本地、私网、云元数据和保留地址；限制重定向次数、响应体积、连接/读取超时，并在每次跳转后重新校验目标 IP。
- 预签名上传限制对象键前缀、MIME、大小、校验和与短有效期；完成接口不信任浏览器上报值，必须以 S3 `HeadObject` 和内容探测结果为准。
- 审计 `payload` 使用字段允许列表，密码、Cookie、Authorization、CSRF、重置令牌、S3 签名和 Halo Token 在进入日志系统前统一脱敏。

### 12.8 测试与完成定义

每个模块只有同时满足以下条件才算完成：

1. Alembic 可从空库升级到最新版本并可回滚最近一次迁移；DDL、ORM、注释和索引一致。
2. OpenAPI 能生成前端客户端且无手写重复 DTO；契约测试覆盖成功响应、每个稳定错误码和权限失败。
3. Service 单元测试覆盖状态机、所有权、逻辑引用、幂等、并发冲突和软删除；PostgreSQL/Redis/S3 集成测试使用真实兼容服务而非只用 Mock。
4. 安全测试覆盖密码爆破、账号枚举、CSRF、开放重定向、存储型 XSS、恶意 Markdown、SSRF、Zip Slip、压缩炸弹和越权访问。
5. 前端测试覆盖刷新保留地址、登录 `returnTo`、主题切换、1024px 断点、模态框焦点、键盘操作、空/错/加载状态和中英文切换。
6. Playwright 端到端主链路覆盖：公众注册 → 邮箱验证 → 登录 → 评论 → 审核；后台登录 → 建文 → 上传封面 → 预览 → 发布 → 前台访问；以及 Halo 预检 → 导入 → 旧 URL 301 → 回滚。另有用例验证未登录评论必定返回 `401 COMMENT_LOGIN_REQUIRED`。
7. SEO 测试直接检查禁用 JavaScript时的首次 HTML、状态码、canonical、hreflang、JSON-LD、sitemap 和 robots；404 不得返回首页内容或 `200`。同时以百度、搜狗、360、神马真实移动 UA 与普通 UA 对照抓取，断言公开路由语义等价且没有爬虫特供内容；验证百度直链 sitemap 不嵌套 index，API 提交只接收已发布公开 canonical URL。
8. CI 固定执行格式化、lint、类型检查、单元测试、集成测试、前端构建、Alembic 升降级检查和依赖漏洞扫描；任一失败不得发布镜像。

### 12.9 推荐实现顺序

1. 先建立目录、配置、错误模型、请求 ID、数据库 Session、Alembic 和测试容器。
2. 实现用户、认证、RBAC、会话、防爆破、审计和后台路由守卫。
3. 实现文章/页面、修订、分类标签、S3 媒体和发布状态机，随后接入 SSR 与 SEO。
4. 实现评论、图库、首页配置、AI 工具、站点状态、统计和邮件任务。
5. 最后实现 Halo 适配器、预检、幂等导入、重定向、回滚和完整验收。

AI 每完成一个步骤都必须运行该步骤的测试并更新 OpenAPI/迁移文件；不得一次生成整个系统后再集中修错。
